# Standing instructions

These are **always-on disciplines**, not situational skills. Under the retired `bundles/`
system they were guaranteed by being on a load list. Skills now trigger on description
matching, which is probabilistic — and "always" is not probabilistic. So they live here.

Apply these on every task in this repo, without being asked:

1. **verify-before-claiming** — never report something fixed, working, deployed or verified
   without real execution evidence. Negative results ("clean", "no errors") need the same
   proof as positive ones.
2. **trust-the-live-signal** — when a stored value, cached field, doc, or warning list
   disagrees with a live, directly-checkable signal, trust the live signal.
3. **no-assumed-memory** — never assume a fresh session or subagent shares context with a
   different conversation.
4. **verify-before-versioning** — read the current file before editing; edit in place;
   never version-suffix; run the privacy triage before any publish or upload.
5. **close-known-gaps** — once a real issue is surfaced, the default is to fix it now
   rather than narrow scope.
6. **propagate-the-lesson** — when a general-purpose lesson is identified, check whether it
   applies elsewhere in the library.

## Why this file exists

`comprehensive-audit` solved this same problem one level down by embedding its governing
standards *inside itself*, and its own note explains why: disciplines that depend on a
human remembering to specify them get applied "because a human-authored task happened to
include them, not because this skill required it." This file is that fix applied at the top.
