## What each skill does

- **canvas-design** — Creates original visual artwork: posters, covers, infographics, marketing visuals.
- **algorithmic-art** — Creates interactive generative art. Produces self-contained HTML artifacts with p5.js.
- **theme-factory** — Applies a consistent visual theme (colour palette + typography) to any artifact.
- **verify-before-versioning** — Before creating any new skill file, or a new version of an existing skill/bundle, always do a fresh, live search of the actual Drive folder right now. Always-on.
- **trust-the-live-signal** — When a stored value or documentation disagrees with a live, directly-checkable signal, trust the live signal. Always-on.
- **no-assumed-memory** — Never assume a fresh session shares memory with a different conversation. Always-on whenever work crosses a session boundary.
- **propagate-the-lesson** — Whenever a genuinely general-purpose lesson or fix is identified, check every bundle for the same applicability. Now also explicitly checks whether a new skill needs registering in comprehensive-audit's own lists, not just added to a bundle. Always-on.
- **close-known-gaps** — Once a real, known issue has been surfaced, the default is to fix it now rather than narrowing scope. Always-on.

## How to trigger each skill

- "Create a poster / visual / cover / design" → canvas-design
- "Make generative art / algorithmic art / animated visuals" → algorithmic-art
- "Apply a theme to this / make this look consistent" → theme-factory
- "Change the design" / "Make the UI look better" / "Redesign this screen" / any frontend
  design, typography, colour, spacing or motion request → impeccable (EXTERNAL, self-triggering)
- verify-before-versioning, trust-the-live-signal, no-assumed-memory, propagate-the-lesson, and close-known-gaps trigger automatically.

## EXTERNAL — installed into the harness, not in this repo

Third-party skills installed as plugins in the AI harness itself. They are deliberately
NOT in the numbered load list above and must never be added to it: there is no file for
them here, so listing one would register as a DEAD LINK in the orphan check. This section
exists purely so a session knows they are available and does not reinvent their guidance.

- **impeccable** — Design fluency for frontend work: one skill, 23 commands, and 58
  deterministic anti-pattern rules covering AI-slop tells (gradient text, purple/violet
  accents, overused faces like Inter and Roboto), WCAG contrast, typography, layout,
  spacing, and motion. Author Paul Bakaus, Apache-2.0, impeccable.style.
  **Self-triggering — no trigger phrase needed.** Its own description already covers
  "change the design", "make the UI look better", redesign, critique, audit, polish,
  colour, spacing and motion requests.
  Installed user-scope via the Claude plugin marketplace (`pbakaus/impeccable`).
  **Never hand-edit it** — it has no local-override mechanism, so any edit is silently
  overwritten on the next update, with nothing announcing the loss. Customisation lives
  in each project's own PRODUCT and DESIGN truth files, generated by its init command.
  Treat its findings as evidence, not orders: a deliberate house choice it flags (dark UI
  for a streaming product, say) should be recorded with a `REVIEWED <date>` marker per
  respect-settled-decisions, not re-litigated every pass.
